# CSV и журналы агентов

Реестр: `workdir/requests.csv`. Первые восемь колонок:

| Колонка | Значение |
|---|---|
| UID | Ключ запроса, передаваемый в JSON как mail_id |
| request_received_at | Время поступления исходного письма на сервер, IMAP INTERNALDATE |
| filename | Исходное имя Excel-вложения |
| outlook_sent_at | Время подтверждения приёма запроса SMTP-сервером |
| outlook_received_at | Время поступления сопоставленного ответа на сервер, IMAP INTERNALDATE |
| output_filename | Имя готового файла: out_ + исходное имя |
| user_sent_at | Время подтверждения приёма письма пользователю SMTP-сервером |
| user_message_id | Message-ID письма пользователю, если доступен |

Далее сохраняются внутренние поля request_id, mailbox, uidvalidity, mail_uid, source_path, sender, status, output_path. Они нужны для корреляции, восстановления и защиты от дублей. UID и request_id содержат один ключ. CSV не содержит паролей.

`workdir/result-mail-handled.json` хранит пары `UIDVALIDITY:UID` уже проверенных
ответных писем. Успешные ответы и письма с неизменяемыми ошибками формата больше
не перечитываются в каждом цикле. Новый исправленный ответ получает новый IMAP UID
и обрабатывается отдельно. Ошибки транспорта и файловой системы в этот файл не
записываются и остаются доступными для повторной попытки.

TS трактуется как временная метка события (timestamp), а не длительность шага. Формат ISO 8601, UTC с явным смещением +00:00. Для Москвы прибавьте три часа. Отсутствующие или исторически неизвестные времена остаются пустыми. Дата из заголовка Date не используется как доказательство получения.

SMTP не возвращает IMAP UID исходящего письма. Вместо него фиксируется RFC Message-ID; это явно другое пространство идентификаторов. Поля отправки не подтверждают доставку конечному адресату. Идентификатор и время приёма сохраняются также в submission-журнале и не меняются при повторном запуске.

Первое обновление CSV новым кодом автоматически добавляет новые поля, не удаляя старые записи. До изменения сохраняется requests.legacy.csv. Перед обновлением остановите все старые экземпляры агентов и затем запустите обновлённый run-agents: старый процесс не должен одновременно записывать прежнюю схему CSV. Исторические времена не восстанавливаются по времени изменения файлов.

## Логи

- `workdir/logs/request-agent.log` — получение одного входящего письма, проверка Excel, подготовка JSON и ошибки.
- `workdir/logs/result-agent.log` — отправка подготовленных JSON, обработка ответов, формирование Excel, отправка пользователям и ошибки.

Работает при run-agents, отдельных request-agent/result-agent, однократных process-inbox/receive. Файлы создаются при начале первого цикла. Есть ротация по 5 МБ, до пяти архивов на каждый агент. Записываются начало опроса, ключи запросов, подтверждения SMTP и исключения. Содержимое писем и реквизиты авторизации специально не выводятся. Папка workdir исключена из Git.
