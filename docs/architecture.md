# Архитектура двух обработчиков

request-agent (PY1) за один проход читает одно письмо planning / IMAP, сохраняет исходный Excel и связь с письмом в CSV, создаёт JSON и оставляет запись в состоянии `prepared`.
result-agent (PY2) за один проход выполняет одну полезную операцию очереди. Приоритет имеет готовый ответ bridge / IMAP: агент извлекает `mail_id`, дополняет исходный Excel значениями `forecast_m1`, `forecast_m2`, `forecast_m3` в трёх отдельных столбцах и отправляет его через planning / SMTP автору как ответ в исходной почтовой цепочке. Если ответа нет, агент отправляет один старейший `prepared` JSON через bridge / SMTP и меняет состояние на `sent`. Тема ответа n8n для маршрутизации не используется.

## Модули

- agents.py — два обработчика и циклический запуск.
- registry.py — CSV requests.csv, блокировка ОС и атомарная замена файла.
- template_excel.py — проверка шаблона, извлечение единственного направления, сопоставление результата и добавление трёх столбцов прогноза.
- internet_mail.py — IMAP/SMTP, MIME-письма и сохранение SMTP-копий в IMAP «Отправленные».
- state.py — журналы отправок, запрет повторов при неоднозначном исходе.
- config.py и cli.py — настройки и команды.
- workflow.py, models.py, excel_io.py — прежние локальные преобразования и совместимость старого контракта. Новые обработчики не используют старый формат направления direction_id как основной ключ.

## Хранилище

WORK_DIR/requests.csv — индекс UID и файлов, исходные IMAP UID и UIDVALIDITY, статусы.
WORK_DIR/jobs/<UID>/source.xlsx — неизменённый исходник; request.json — отправленный контракт; response.json — ответ; XLSX с исходным именем — дополненная книга.
В этой же папке отдельные журналы отправки запроса и результата.

Каждый агент имеет отдельную блокировку процесса; доступ к CSV защищён общей короткой блокировкой. Поддерживаются два процесса разных ролей с общим WORK_DIR на локальном диске. Основной жизненный цикл записи: `prepared → sent → completed`.

## Ограничения

SMTP принятие не гарантирует доставку. Сбой после начала отправки требует ручной проверки. From-фильтр не заменяет проверку подлинности почтовой инфраструктурой.
Ответ без UID не сопоставляется по времени или последнему запросу. Несколько прогнозов для одной строки без периода не суммируются.
Точное сохранение сложных объектов Excel необходимо проверять на реальном шаблоне. JSON запроса соответствует `schemas/shipment_forecast_input.schema.json`; n8n должен возвращать тот же `mail_id`.
Полная инструкция и примеры в README.md.
