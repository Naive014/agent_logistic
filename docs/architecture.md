# Архитектура двух обработчиков

request-agent (PY1) читает planning / IMAP, сохраняет исходный Excel и связь с письмом в CSV, отправляет JSON через bridge / SMTP в корпоративную почту.
result-agent (PY2) читает bridge / IMAP, извлекает UID и прогнозы, дополняет исходный Excel и отправляет его через planning / SMTP автору исходного письма (поле sender в CSV).

## Модули

- agents.py — два обработчика и циклический запуск.
- registry.py — CSV requests.csv, блокировка ОС и атомарная замена файла.
- template_excel.py — извлечение направлений из исходной книги, сопоставление результатов по направлению и периоду, добавление столбца.
- internet_mail.py — IMAP/SMTP и MIME-письма.
- state.py — журналы отправок, запрет повторов при неоднозначном исходе.
- config.py и cli.py — настройки и команды.
- workflow.py, models.py, excel_io.py — прежние локальные преобразования и совместимость старого контракта. Новые обработчики не используют старый формат направления direction_id как основной ключ.

## Хранилище

WORK_DIR/requests.csv — индекс UID и файлов, исходные IMAP UID и UIDVALIDITY, статусы.
WORK_DIR/jobs/<UID>/source.xlsx — неизменённый исходник; request.json — отправленный контракт; response.json — ответ; `out_<исходное имя>.xlsx` — дополненная книга.
В этой же папке отдельные журналы отправки запроса и результата.

Каждый агент имеет отдельную блокировку процесса; доступ к CSV защищён общей короткой блокировкой. Поддерживаются два процесса разных ролей с общим WORK_DIR на локальном диске.

## Ограничения

SMTP принятие не гарантирует доставку. Сбой после начала отправки требует ручной проверки. From-фильтр не заменяет проверку подлинности почтовой инфраструктурой.
Ответ без UID не сопоставляется по времени или последнему запросу. Несколько прогнозов для одной строки без периода не суммируются.
Точное сохранение сложных объектов Excel необходимо проверять на реальном шаблоне. Новый JSON-контракт и возврат UID нужно согласовать с n8n.
Полная инструкция и примеры в README.md.
