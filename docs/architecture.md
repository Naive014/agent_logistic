# Архитектура

Автор ТЗ → planning / IMAP → Python → bridge / SMTP → корпоративный Exchange → n8n.
Ответ n8n → bridge / IMAP → Python → planning / SMTP → автор ТЗ с Excel.

## Модули

- config.py — параметры двух ящиков, TLS и таймаутов.
- internet_mail.py — соединения IMAP/SMTP, чтение без изменения Seen, фильтры отправителя и темы, формирование MIME-писем.
- models.py — контракт запросов и ответов.
- excel_io.py — преобразование Excel и JSON-моделей.
- state.py — атомарная запись состояния и защита от повторной SMTP-отправки.
- workflow.py — координация этапов, корреляция request_id, проверка направлений.
- cli.py — однократные команды запуска.

Корпоративный Exchange доступен агенту только через почтовый обмен. EWS и MAPI в текущем агенте не используются; старый неиспользуемый модуль exchange.py удалён. Исходный репозиторий агента Коля остаётся отдельно.

## Границы гарантий

Журнал фиксирует приём SMTP, не доставку. При неоднозначном исходе требуется ручная проверка. Флаг Seen выставляется после успешной обработки; локальный журнал защищает от повторной отправки, если выставить флаг не удалось.
Изменение UIDVALIDITY или повторная отправка исходного письма создают новую идентичность.
Ответы принимаются только от настроенного From; аутентификация домена должна обеспечиваться почтовой инфраструктурой.
Источник окончательного адреса получателя Excel — локально сохранённый автор ТЗ, не поля входящего ответа n8n.
Поддерживается запуск одного обработчика; несколько одновременно запущенных процессов не являются поддерживаемым режимом, несмотря на исключительное создание записи отправки.
