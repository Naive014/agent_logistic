# Два почтовых агента для ТЗ

Актуальная структура CSV, временные метки и отдельные логи описаны в [docs/audit.md](docs/audit.md). Готовый файл теперь называется `out_<исходное имя>.xlsx`, например `out_Пример ТЗ.xlsx`.

## Текущая схема

request-agent (PY1 на схеме) читает непрочитанные письма [FORECAST_INPUT] с .xlsx из agent_planing@logrocket.ru. Сохраняет исходный файл, записывает связь UID и файла в workdir/requests.csv, отправляет JSON через agent_planing_to_outlook@logrocket.ru на корпоративный адрес.

result-agent (PY2 на схеме) читает ответы из agent_planing_to_outlook@logrocket.ru, находит исходный Excel по UID, добавляет один столбец «Прогноз» и отправляет результат из agent_planing@logrocket.ru автору исходного письма. Адрес берётся только из поля sender сохранённой записи CSV; поля получателя в JSON n8n игнорируются.

## Запуск

Нужен Python 3.11+. Из каталога проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Создайте .env по .env.example только на новом компьютере. Не перезаписывайте уже заполненный .env.

Запуск обоих агентов одной командой из каталога проекта:

```powershell
.\.venv\Scripts\shipment-forecast-agent.exe run-agents
```

Команда держит два отдельных процесса в одном окне. Ctrl+C останавливает оба: сначала ожидает завершения текущих операций, затем при необходимости завершает зависший процесс. Если один процесс неожиданно завершился, второй тоже останавливается с сообщением об ошибке. Обычные ошибки почтового соединения обрабатываются внутри агентов с повтором следующего опроса. Не запускайте одновременно общий запуск и отдельные агенты. Это локальная команда, не HTTP endpoint; окно должно оставаться открытым, компьютер — включённым. Автозапуск после перезагрузки не устанавливается.

Либо по отдельности, в двух окнах PowerShell:

```powershell
.\.venv\Scripts\shipment-forecast-agent.exe request-agent
```

```powershell
.\.venv\Scripts\shipment-forecast-agent.exe result-agent
```

Это реальные обработчики с отправкой почты. Проверка каждые POLL_INTERVAL_SECONDS (по умолчанию 30). Остановка Ctrl+C. Для одного прохода добавьте --once. process-inbox и receive — синонимы однократной обработки запросов и ответов новой цепочки.
Автозапуск после перезагрузки не установлен. Один экземпляр каждого агента; оба процесса должны использовать общий WORK_DIR на локальном диске. Блокировки CSV снимаются ОС при завершении процесса.

check-mail проверяет авторизацию без отправки; self-test-mail отправляет тест техническому ящику самому себе.

## Настройки

- MAILBOX_NAME / MAILBOX_PASSWORD — технический ящик agent_planing_to_outlook@logrocket.ru.
- INPUT_MAILBOX_NAME / INPUT_MAILBOX_PASSWORD — ящик входящих ТЗ agent_planing@logrocket.ru.
- INTERNAL_OUTLOOK_EMAIL — smirnovis@sibur.ru.
- N8N_RESPONSE_SENDER — ожидаемый From ответа; пустое значение использует INTERNAL_OUTLOOK_EMAIL.
- RESULT_MAILBOX — устаревшая настройка, новым обработчиком не используется. Получатель результата — исходный sender из CSV.
- INPUT_SUBJECT_PREFIX — [FORECAST_INPUT].
- N8N_REQUEST_SUBJECT_PREFIX — [N8N_FORECAST_REQUEST].
- N8N_RESPONSE_SUBJECT_PREFIX — [N8N_FORECAST_RESULT].
- EXCEL_SHEET — лист ТЗ; пустое значение означает активный лист.
- EXCEL_HEADER_ROW — номер строки заголовков, по умолчанию 1.
- FORECAST_START_MONTH и FORECAST_HORIZON_MONTHS больше не используются новым процессом: ppr_month берётся из текущего календарного месяца на компьютере агента.
- TRUSTED_REQUESTERS — разрешённые отправители через запятую; пустой список разрешает всех.
- Серверы общие для двух ящиков: imap.beget.com:993, smtp.beget.com:465, TLS.

Пароли находятся только в локальном .env, исключённом из Git. SEND_RESULTS_TO_REQUESTER относится только к старым функциям: новый result-agent всегда возвращает готовый файл исходному автору из CSV через INPUT_MAILBOX_NAME.

## Excel

Перед отправкой запроса проверяется наличие всех 21 заголовков из согласованного шаблона «Пример ТЗ.xlsx». Их порядок, регистр и лишние пробелы не важны, дополнительные столбцы допускаются. Полный список и поведение при ошибке описаны в [docs/input-validation.md](docs/input-validation.md). Значения обязательны только для пункта отгрузки и региона доставки; остальные поля могут быть пустыми.

В ppr_month передаётся текущий календарный месяц компьютера агента (YYYY-MM), независимо от периодов в Excel. Любая колонка месяца сохраняется как прочие исходные данные. В ответе ожидается ровно одно значение forecast на пару пункт–регион, даже если ответ содержит дополнительные поля дат. Несколько прогнозов на одно направление отклоняются, не суммируются. Повторные строки одного направления получают одно и то же число.

Результат — копия исходной книги с добавленным справа столбцом «Прогноз» на выбранном листе. Остальные ячейки, обычные стили, формулы и листы сохраняются средствами openpyxl. Если столбец «Прогноз» уже есть, обработчик отказывается перезаписывать его.
Поддерживается .xlsx; макросы и специфические объекты Excel не гарантируются. Для сложного шаблона с объединениями, таблицами, рисунками и защищёнными листами требуется отдельная проверка на реальном файле. Исходник хранится неизменённым.

## UID и CSV

В теме запроса: [N8N_FORECAST_REQUEST] RQ-<32 hex символа>.
Ключ создаётся из адреса входящего ящика, UIDVALIDITY, UID письма, имени и содержимого вложения. Это не голый IMAP UID: он не уникален между ящиками. Несколько Excel в одном письме получают отдельные ключи.

CSV хранит request_id, mailbox, uidvalidity, mail_uid, filename, source_path, sender, status, output_path.
В workdir/jobs/<UID>/ лежат source.xlsx, request.json, response.json, итоговый `out_<исходное имя>.xlsx` и журналы отправок.

JSON запроса:

```json
{
  "mail_id": "RQ-0123456789abcdef0123456789abcdef",
  "request_id": "RQ-0123456789abcdef0123456789abcdef",
  "ppr_month": "2026-09",
  "directions": [
    {"shipment_point_name": "Завод", "delivery_point_name": "Область"}
  ]
}
```

Запрос содержит mail_id, request_id (тот же ключ), ppr_month (текущий месяц) и directions. horizon_months и periods не передаются. Месяц фиксируется при создании request.json и не меняется при повторе сохранённого запроса. Ранее сохранённые request.json автоматически не переписываются и запросы не пересылаются.

## Ответ

Тема начинается с [N8N_FORECAST_RESULT]. Отправитель должен совпадать с настройкой. Ровно одно JSON-вложение. JSON обязан содержать mail_id с тем же ключом, что был в запросе. Разрешено поле верхнего уровня либо одинаковое mail_id внутри строк data/forecasts. Одной темы недостаточно. Если ключ в теме указан и расходится с mail_id, ответ отклоняется.

Допускаются:
- одиночный объект с shipment_point_name, delivery_point_name, forecast (даты необязательны и игнорируются);
- массив таких объектов;
- объект с mail_id, status: ok, data: [объекты] и необязательным row_count;
- совместимый контейнер forecasts с shipping_point, delivery_region, period, forecast.

Пример:

```json
{
  "mail_id": "RQ-0123456789abcdef0123456789abcdef",
  "status": "ok",
  "row_count": 1,
  "data": [
    {"shipment_point_name": "Завод", "delivery_point_name": "Область", "forecast": 433.18}
  ]
}
```

Ответ без mail_id в JSON, в том числе ранее полученный одиночный пример Ильи, автоматически не обрабатывается. Пустой data не является готовым ТЗ. Ошибки [N8N_FORECAST_ERROR] не считаются результатами и не обрабатываются этим агентом.

## Ошибки и повторы

Письма читаются без изменения Seen; успешные помечаются прочитанными. Не открывайте новые ТЗ в другом клиенте до обработки.
Неуспешные письма остаются непрочитанными, ошибка записывается в консоль, остальные письма продолжают обрабатываться.
Записи отправки smtp_accepted предотвращают дубли. Запись submitting после сбоя блокирует повтор до ручной проверки логов: нельзя безусловно пересылать письмо, которое сервер мог принять.
Состояние sent означает приём запроса SMTP-сервером; completed — приём письма с итоговым Excel сервером, не подтверждение доставки адресату.
Повторно пересланное исходное письмо с новым UID считается новым запросом.

## Совместимость и проверка

Старые команды prepare, convert и send сохраняются для старого контракта; не используйте send для нового CSV-процесса, поскольку он не создаёт запись нового реестра. Старые JSON-схемы в contracts относятся к этому прежнему формату.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты не отправляют реальные письма. Полный цикл с реальным n8n и вашим шаблоном Excel необходимо проверить отдельно. Автоматический push в GitHub и запуск фоновых обработчиков при изменении кода не выполняются.

В CSV внутреннее имя колонки request_id сохранено для совместимости; её значение передаётся как mail_id. Формат ключа RQ-… не изменён. Старые отправленные запросы не пересылаются автоматически. После изменения кода перезапустите run-agents; на уже отправленные запросы обработчик должен вернуть тот же ключ в mail_id.
